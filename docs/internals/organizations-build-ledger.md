## Current integration milestone

The requested follow-up covers three linked slices: durable scoped-launch recovery, a
dedicated GitHub repository for each Organization's portable knowledge, and a guided
Architect conversation that works with any configured text-generation provider. The
repository sync stores remote records as attributed reference material; importing a
repository creates a local draft and never imports credentials, local Project access,
resource permits, or publication authority. An Organization-scoped shared memory
record can be saved as a local unverified reference after explicit review. The
guided Architect uses saved conversation and current draft context, and applies
a reply's related proposals in
one validated draft revision. Focused Git/SQLite tests exercise link, load, automatic
sync, remote changes and deletion, conflict resolution, visibility drift, and
concurrent push. In an isolated browser run, Organization create, Designer
walkthrough draft, configured provider/model selection, Repository preview,
mobile 390 px width without page overflow, and reload persistence were observed.
Actual GitHub account pushes and paid provider replies have not been performed.
The Linux x64 AppImage was rebuilt from this worktree and installed at
`/home/josephh/Applications/T3-Code.AppImage`; its checksum matches the build
artifact, and the desktop and URL launchers resolve to that path. Focused final
checks passed for the Git/Architect/launcher set (32 tests) and crash recovery
set (46 tests), along with web and contracts TypeScript checks.

Crash recovery includes a durable launch journal, a singleton broker, explicit
process-identity reconciliation, and a server-update quiescence barrier. An
identity-less dispatch remains held for manual recovery because the runtime cannot
prove that it stopped. The live autonomous Organization activation gate remains
closed; the complete Phase 2 operating loop described in A16 has not yet been
validated or enabled.
